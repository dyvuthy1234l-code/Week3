គ្រឹះស្ថានសិក្សា៖ សាកលវិទ្យាល័យភូមិន្ទភ្នំពេញ (RUPP) | ឆ្នាំទី ៣ - ថ្នាក់ A3

មុខវិជ្ជា៖ Front-End Web Application Development (FEWAD)

ផ្នែកទី១ (ថ្ងៃទី១)៖ ១.៦. Semantic HTML (HTML ស៊ីមែនទិក)

និយមន័យ (Definition):
Semantic HTML គឺជាការប្រើប្រាស់ HTML Tags ណាដែលមានអត្ថន័យបញ្ជាក់យ៉ាងច្បាស់លាស់អំពីតួនាទី និងប្រភេទនៃមាតិកានៅខាងក្នុងវា ទាំងចំពោះមនុស្ស (អ្នកអភិវឌ្ឍន៍) និងចំពោះម៉ាស៊ីន (Web Browser, Search Engine Bots, Screen Readers) ជាជាងការប្រើ Tags ទូទៅដែលគ្មានអត្ថន័យដូចជា <div> និង <span>។

ស្លាកសញ្ញា Semantic សំខាន់ៗ និងតួនាទី៖

  • <header>: ផ្នែកក្បាលទំព័រ ឬផ្នែកណែនាំ (ផ្ទុក logo, ចំណងជើង, search)។
  • <nav>: ផ្នែកនៃតំណភ្ជាប់មឺនុយសម្រាប់ធ្វើដំណើរក្នុងវេបសាយ (Navigation)។
  • <main>: ផ្ទុកមាតិកាស្នូលចម្បងនៃទំព័រ (មានតែមួយគត់ក្នុងមួយទំព័រ)។
  • <section>: កំណត់ប្លុកមាតិកាដែលមានប្រធានបទជាក់លាក់ណាមួយ។
  • <article>: ប្លុកមាតិកាឯករាជ្យដែលអាចឈរតែឯងបាន (ឧ. អត្ថបទព័ត៌មាន, Blog post)។
  • <aside>: មាតិកាបន្ថែម ឬ Sidebars ដែលពាក់ព័ន្ធដោយប្រយោលជាមួយមាតិកាចម្បង។
  • <footer>: ផ្នែកបាតក្រោមនៃទំព័រ (ព័ត៌មានរក្សាសិទ្ធិ, ទំនាក់ទំនង, Social links)។

សារៈប្រយោជន៍ចម្បងនៃ Semantic HTML៖

  1. SEO (Search Engine Optimization): ជួយឱ្យ Search Engine Bots (ដូចជា Google, Bing) យល់ច្បាស់អំពីរចនាសម្ព័ន្ធមាតិកា ធ្វើឱ្យវេបសាយទទួលបានចំណាត់ថ្នាក់ខ្ពស់ក្នុងការស្វែងរក។
  2. Web Accessibility (a11y): ជួយឱ្យជនពិការភ្នែកដែលប្រើប្រាស់ Screen Readers អាចរុករកផ្នែកនីមួយៗនៃទំព័របានរហ័ស និងត្រឹមត្រូវ។
  3. Code Readability & Maintainability: ធ្វើឱ្យកូដមានរបៀបរៀបរយ ងាយស្រួលអាន ងាយយល់ និងងាយកែសម្រួលសម្រាប់ក្រុមការងារ Developers។

ផ្នែកទី២ (ថ្ងៃទី១)៖ ១.៧. Embedding External Content (ការបង្កប់មាតិកាខាងក្រៅ)

HTML ផ្តល់នូវស្លាកចំនួន ៣ សម្រាប់បង្កប់ឯកសារ ឬមាតិកាខាងក្រៅ (ដូចជា PDF, វីដេអូ, ផែនទី) ចូលក្នុងទំព័រវេបសាយ៖

Element គោលបំណងចម្បង (Primary Purpose) ចំណុចខ្លាំង (Strengths) ចំណុចខ្សោយ (Limitations)
<iframe> បង្កើត Inline Browsing Context ដាច់ដោយឡែកមួយក្នុងទំព័រ។ ពេញនិយមបំផុតសម្រាប់បង្កប់ YouTube Videos, Google Maps, និងទំព័រវេបសាយខាងក្រៅ។ មានសុវត្ថិភាពខ្ពស់ដោយអាចប្រើ Attribute sandbox, គាំទ្រលើគ្រប់ Browser ទាំងអស់។ ត្រូវការទំហំ Memory បន្ថែម ព្រោះវាបង្កើត Window ដាច់ដោយឡែកមួយទៀត។
<embed> ជា Self-closing Tag ប្រើសម្រាប់ផ្ទុក Plugin ខាងក្រៅ ឬឯកសារ Media ដូចជា PDF ដោយផ្ទាល់។ សរសេរកូដខ្លី សាមញ្ញ ងាយស្រួលប្រើសម្រាប់បង្ហាញ PDF ផ្ទាល់លើទំព័រ។ គ្មាន Fallback Content (មិនអាចសរសេរអក្សរបម្រុងទុកពេល Error ឬពេល Browser មិនគាំទ្រឡើយ)។
<object> ជា Container ពហុបំណងដែលអាចផ្ទុកឯកសារបានច្រើនប្រភេទ (PDF, រូបភាព, អូឌីយ៉ូ, កម្មវិធីខាងក្រៅ)។ អនុញ្ញាតឱ្យសរសេរ Fallback Content នៅខាងក្នុង ប្រសិនបើ Browser មិនអាចបង្ហាញឯកសារនោះបាន (ឧ. ដាក់ Link ឱ្យទាញយក PDF)។ Syntax មានភាពស្មុគស្មាញជាងបន្តិចបើធៀបនឹង Tag ផ្សេងទៀត។

ផ្នែកទី៣ (ថ្ងៃទី២)៖ Absolute Address vs Relative Address

១. Absolute address (Absolute URL) នៅក្នុងវេបសាយ

និយមន័យ៖ គឺជាអាសយដ្ឋានពេញលេញមួយដែលចង្អុលបង្ហាញទីតាំងពិតប្រាកដនៃធនធាន (Resource: ទំព័រ, រូបភាព, ឯកសារ) នៅលើប្រព័ន្ធអ៊ីនធឺណិតទាំងមូល។
រចនាសម្ព័ន្ធ៖ វាតែងតែរួមបញ្ចូលនូវ Protocol (https://) + Domain Name (www.example.com) + Path (/content/work.html)។
ឧទាហរណ៍៖ https://front-end.com.kh/content/work.html
ការប្រើប្រាស់៖ ប្រើសម្រាប់បង្កើតតំណភ្ជាប់ទៅកាន់គេហទំព័រខាងក្រៅ (External Links) ឬភ្ជាប់ទៅកាន់បណ្ណាល័យ CDN ខាងក្រៅ។

២. Relative address (Relative URL) នៅក្នុងវេបសាយ

និយមន័យ៖ គឺជាអាសយដ្ឋានដែលចង្អុលបង្ហាញទីតាំងនៃឯកសារមួយដោយ ផ្អែកលើទីតាំងបច្ចុប្បន្ននៃឯកសារកំពុងដំណើរការ ដោយមិនមានផ្ទុកឈ្មោះ Protocol ឬ Domain Name ឡើយ។
ទម្រង់នៃការសរសេរ៖

  • ក្នុង Folder ជាមួយគ្នា៖ work.html ឬ ./work.html
  • ក្នុង Folder រង (Child folder)៖ content/work.html ឬ image/HTML1.0.png
  • ថយក្រោយចេញទៅក្រៅមួយកម្រិត (Parent folder)៖ ../index.html ឬ ../image/HTML1.0.png
  • ផ្អែកលើ Root នៃវេបសាយ៖ /content/work.html

អត្ថប្រយោជន៍ចម្បងនៃ Relative URL៖ ជួយឱ្យគម្រោងវេបសាយមានភាពងាយស្រួលក្នុងការផ្លាស់ទី (High Portability)។ នៅពេលអ្នកផ្លាស់ប្តូរទីតាំង Folder វេបសាយលើកុំព្យូទ័រ (Localhost) ឬ Upload ទៅកាន់ Cloud Hosting ដូចជា Netlify តំណភ្ជាប់រូបភាព និងទំព័រទាំងអស់នឹងនៅតែដំណើរការយ៉ាងត្រឹមត្រូវ ១០០% ដោយមិនបាច់កែសម្រួលឡើយ។

ផ្នែកទី៤ (ថ្ងៃទី២)៖ ជំហាននៃការដាក់ឱ្យដំណើរការវេបសាយលើ Netlify (Deploy Website to Netlify Drop)

  1. ចុះឈ្មោះគណនី៖ ចូលទៅកាន់ https://app.netlify.com/signup រួចចុះឈ្មោះតាម Google ឬ GitHub។
  2. ផ្ទៀងផ្ទាត់ Email៖ ចូលទៅកាន់ Gmail រួចចុចលើប៊ូតុង Verify email។
  3. បំពេញព័ត៌មាន Profile៖ បំពេញ Name, Role (Junior Web Developer), Team Name រួចចុច Continue to deploy។
  4. ចូលទៅកាន់ Netlify Drop៖ ចូលទៅកាន់តំណភ្ជាប់ https://app.netlify.com/drop។
  5. បង្ហោះ Folder វេបសាយ (Drag & Drop): ចាប់ទាញ Folder វេបសាយរបស់អ្នក (ដែលផ្ទុក index.html) ទម្លាក់ចូលទៅក្នុងប្រអប់រង្វង់ Drag and drop your project folder here។
  6. ប្តូរឈ្មោះវេបសាយ (Site Name): ចុចលើ Quick setup -> Change site name (ប្តូរឈ្មោះតាមទម្រង់ត្រកូល និងឈ្មោះ ឧ. yourname)។
  7. អាសយដ្ឋានផ្សាយផ្ទាល់ (Live URL): វេបសាយរបស់អ្នកនឹងដំណើរការផ្សាយផ្ទាល់លើពិភពលោកតាមរយៈ https://yourname.netlify.app/។
  8. របៀប Update កូដថ្មី (Redeploy): ចូលទៅកាន់គម្រោងរបស់អ្នក -> ចុចលើ Tab Deploys -> ចាប់ទាញ Folder ដែលបានកែប្រែទម្លាក់ចូលម្តងទៀត Netlify នឹង Update កូដថ្មីដោយស្វ័យប្រវត្តិភ្លាមៗ។
